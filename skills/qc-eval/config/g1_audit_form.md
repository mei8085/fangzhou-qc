## 右侧「评测打分」（只读，标注人已提交）

不是质检要填的表单。采集时已写入各模型 `evaluation.json`。

- 执行过程 1–10 + 归因标签 + 维度备注
- 执行产物 1–10 + 归因标签 + 维度备注
- 产出物反馈

页面没有综合评分、总分、均分等聚合分。API / `evaluation.json` 里若出现这些字段，不要写进交付备注。

## 右侧「质检」（要填）

### 请选择该任务的质量 *必填

高 / 中 / 低 / 不可用

五个模型共用同一判定。飞书「任务质量（题目质量）」映射：高质量→高，合格→中，不合格/红线→不可用。

### 任务质量备注

占位：请输入备注

### 请选择该用户的反馈质量 *必填

完全可用 / 部分可用 / 完全不可用

飞书「反馈质量（作业质量）」映射：高质量→完全可用，合格→部分可用，不合格/红线→完全不可用。

### 反馈质量备注

占位：请输入备注

按档位写 1～2 句：高质量用「和产物实测情况一致，评分正确」；合格写清和产物实际情况一致或不符合的点，并点名哪一项评分偏高或偏低；不合格点名红线并按脏数据标签写一句。不要写「缺口」。缺功能、缺控件、没写全，改用缺陷、缺失、问题或不完整。不要写缺主语的「，与备注相符」，改成「实际情况与备注相符」。不要写「仍在」「说得过头」，直接写与实际情况相符或不符。不要写「可核」「也可核」「能核」，改成「和实际验证结果相符」。

### 审核理由 *必填

占位：例如：响应内容偏离任务要求 / 输出代码可直接运行 / 触及红线敏感词...

必须用本页反馈质量选项词收束：`反馈完全可用` / `反馈部分可用` / `反馈完全不可用`。不要写飞书档位词（高质量 / 合格 / 不合格），也不要写「故高质量」「故合格」「反馈质量为高质量」。

### 请选择脏数据标签

可多选。页面没有「非脏数据」按钮，不选即非脏数据。

飞书「【G1】Sxxx脏数据标签」下拉原文（无空格、半角冒号）为：`模型资源问题:API请求超时/轨迹大量error`、`OpenClaw/Hermes框架问题`、`用户问题:低质量任务`、`用户问题:敷衍恶意打分`、`用户问题:AI打分/AI评价`、`用户问题:用户切换模型错误`、`用户问题:LLM任务测试VLM能力`、`其他`。飞书非脏数据留空，不要填「非脏数据」。

- 模型资源问题：API 请求超时 / 轨迹大量 error
- OpenClaw/Hermes框架问题
- 用户问题：低质量任务
- 用户问题：敷衍恶意打分
- 用户问题：AI 打分 / AI 评价
- 用户问题：用户切换模型错误
- 用户问题：LLM任务测试VLM能力
- 其他

底部按钮：返回列表 / 保存草稿 / 打回 / 提交审核

用户明确要求填写网页表单时，用 `node skills/qc-eval/scripts/fill_g1_audit_form.js --task-id <任务ID>` 按填写文件写入「质检」面板，并只点「保存草稿」。禁止提交审核。
